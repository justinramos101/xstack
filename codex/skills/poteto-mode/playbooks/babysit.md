### Babysit

Work the lowest unmerged PR first. Opening a PR alone does not start a babysit. An Autopilot owner’s assignment includes it. Follow [Codex runtime](../references/host-runtime.md) and the active host’s PR and watcher tools.

1. **Declare the mode before polling.** `drive` works until the PR is merge-ready. In `threads-only`, read and address the review threads in step 4, then report the results. In `check`, read status once and report without making changes. Use a single watcher per stack.
2. **Read the forge verdict.** Prefer the active host’s PR tools. With the bundled GitHub `scripts/watch-pr/watch-pr`, pass `--pr <number>` for a named PR. Add `--stack` for its connected open stack. For a frozen queue, use `--queued-stack --stack-prs <n,...>` with the same comma-separated bottom-to-top list on every restart. Add `--status-only` for a single read. On Origin, use `origin pr view <pr> --checks` and `origin pr thread list <pr>`, then `origin pr checks <pr> --watch` when driving. Rearm an active-session watcher after a push according to its event delivery rules.
3. **Handle conflicts, then review threads, then CI.** Report a conflict or stale base to the owner with the branch to rebase and any new callers to reconcile. Babysitting alone grants no authority to rebase, retarget or force-push. An Autopilot owner follows its playbook’s update rules. Give a plausible infrastructure failure one fresh build and investigate repeated failures.
4. **Verify review claims against the code.** Follow the [Bugbot triage rubric](../references/bugbot-triage.md). Batch proven fixes on the PR that owns them and push before replying with evidence. Reply through a structured PR tool or pass comment text as data via `gh api --input` or `origin pr thread reply --body-file`. Escalate security, auth, billing and data issues when they need operator judgment.
5. **Stop at the requested verdict.** For the GitHub watcher, a single or stack `READY` ends the drive. For a queue, use its frozen bottom-to-top PR list. Report a blocker-free `WAITING` with reason `merge-queue` as ready, follow `ADVANCE` if someone else lands the frontier, and stop on `COMPLETE`. For Origin, require mergeable status, green checks and no blocking threads. A pending owner approval remains a wait. A merge requires a separate grant through the [Shipping playbook](shipping.md).
