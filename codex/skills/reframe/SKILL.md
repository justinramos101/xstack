---
name: reframe
description: "Use $reframe when you can describe what you're building and want the expert terms to ask for it precisely."
---

Start with the user's description and the relevant files or code they point to. If the evidence fits more than one problem, give two or three plausible interpretations. For each, name the problem and the sign that would distinguish it. Say which interpretation fits best and why.

1. Give 8–12 terms for the most likely problem, ranked by how much each would change what gets built. Define each in one plain sentence, identify the part of the user's description it names, and show what the term lets them ask an agent to do.
2. For each term, link to a project, paper, or system that uses it in that sense. Open the source and check the usage. Drop any citation you cannot verify.
3. Draw on two or three neighboring fields that have solved a similar problem. Explain what carries over, where each analogy breaks, and which terms the user can borrow.
4. Identify any overlooked concern that would change the request. Finish with the user's description rewritten in the new vocabulary.
